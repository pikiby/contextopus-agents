# 0.5.0 — Native profile checks and precise contracts

Compared with 0.4.0, the procedures distinguish native registration from direct
profile handoff. When the selected host method requires a stored definition,
inspect it, create it when absent, compare/update stale settings and verify it.
The agent chooses the host's own skills and tools. Contextopus stores and resolves
profiles; it does not register or launch native agents itself.

Profile/team schemas now declare their required model or role fields and reject
inappropriate fields before execution. Team resolution includes the complete
profile, team instructions and main-agent rules. Context-specific instruction
binding belongs to Workspace; Agents remains independently usable.

## Update and verification

Requires Core >=1.7,<2; the coordinated release uses Core 1.8.0. Use
`contextopus modules update agents --source /path/to/agents` with the extracted
release folder. Existing profiles, teams, settings and indexes are preserved.
Refresh the procedures and deliver updated skills through the host's normal integration.

Local module tests and installed-artifact checks passed with synthetic embeddings.
These checks do not prove native profile loading or execution in every client.
See [installation and usage](../../README.md).
